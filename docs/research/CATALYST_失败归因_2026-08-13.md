# CATALYST v1 失败归因:逐案例阅读 + 机制链(2026-08-13)

**问题**:同协议扫评下,GRPO 采样口径全面强于 CATALYST(step 50 对齐点:pass@1 50.6% vs 41.0%,pass@3 71.9% vs 59.0%;CATALYST 最好点 step 60 的 pass@3 61.5% 仍低于 GRPO step 50)。"GRPO + 专家经验"不应弱于 GRPO——本文从具体轨迹出发定位原因。

**方法**:亲自阅读扫评轨迹(task 2546/2472/2436 全部 episode)+ 全量统计(每 checkpoint 512 条采样轨迹)+ 训练期 rollout_log 按臂分层(CATALYST 10,008 条 / GRPO 12,800 条)+ 代码与遥测核对。

---

## 一、案例:失败长什么样

**Task 2472「put two spraybottle in toilet」,CATALYST step 50(GRPO 3/4 成,CATALYST 0/4)**:

- 第 1 步直奔 **toilet(目标容器)**,无任何探索计划;
- 第 5 步已拿到 spraybottle 2,随后**拎着瓶子在 cabinet 1 与 toilet 1 之间来回踱步 20 步**,think 反复写"Wait, 我还得去拿第二个喷瓶"(瓶子就在手里);
- 第 26 步才放下第一个瓶子,30 步耗尽。

GRPO 同任务:countertop→take→toilet→put→countertop→take→toilet→put,11 步结束。每步 think 显式记账("cd 2 已在抽屉,还差一个")。

**Task 2546「put two cd in drawer」**:CATALYST 0/4,四条全部撞 max_steps。典型 think:"the CD **must have been taken by someone else**"、"the system **isn't tracking it properly**"——凭空断言未观察到的事实;全程从未探索 cd 1 所在的 sidetable。

失败模式不是"探索不足",是**工作记忆崩坏 + 无据断言**。

## 二、三个量化指纹(512 条/点,GRPO 为对照)

| 指纹 | GRPO | CATALYST |
|---|---|---|
| think 以 "Wait" 开头(评测) | 0.0–0.1% 恒定 | 11%(s30)→ **61.9%(s50)**→ 10%(s60/70) |
| think 以 "Wait" 开头(训练) | 0.0–0.1% 全程 | 0.2%(s1-25)→ **9.4%(s26-50)**→ 8.0% |
| think 词数(训练) | 40 → 86 → **161** → 107(自发学会多想) | 51 → 42 → 44(**被钉死不涨**) |
| 状态幻觉率(评测 s50) | 4.7% | **9.6%** |
| 每决策 token(评测) | 248–291 | 87–106 |

GRPO 的 RL 自己发现了"长推理有回报"(think 4 倍增长);CATALYST 的 think 长度被锚死在开局水平。"Wait" 口癖是 CATALYST 独有的训练注入。

## 三、机制链:上下文级 off-policyness 从侧门回来了

### 3.1 泄漏源(数据事实)

**hint 臂成功轨迹(=重放池入池样本)中,21.0%(361/1715)的 think 明确引用提示**:

> "Based on **the reference**, the peppershaker is likely in one of the cabinets."
> "**The reference mentioned** the laptop is on the sofa."
> "Wait, **the instruction says** I should go back to desk 1."

### 3.2 剥提示重放 = 注入反事实监督(代码事实)

`catalyst.py::build_replay_samples`:每条目每步出 1 个**单 decision 快照**,prompt 是剥掉 hint 的前缀,response 用原采样 token ids。两处错配:

1. **目标错配**:被 BC 的 decision 若引用提示,模型被训练成在无参考的上下文里说"the reference mentioned..."——凭空引用;
2. **前缀错配**:即使目标 decision 干净,**前缀里学生往轮引用 hint 的 think 原样保留**(只删 hint 文本本身)——模型学到"前文凭空引用参考是正常语篇,请继续"。

后果:无据断言事实(→评测的"别人拿走了/系统没记录")、开局直奔目标位置(hint 轨迹知道东西在哪,不探索;BC 把"神谕步态"克隆进无知上下文)、"Wait" 语篇钩子无指涉泛滥。

### 3.3 为什么 w 门没防住(理论要点)

w = min(1, e^{(logπ+H)/τ}) 的零点自校准依赖 **E[φ]=0 对学生自身分布内样本成立**。剥提示后样本在上下文层面已经离策略,该假设恰在需要防守时失效;且 teacher forcing 下只有泄漏短语的**第一个 token** 意外(w 小),后续 token 条件于前文泄漏 token,logp 不低,w≈1 照常放行。实测 w_mean 0.87–0.94、p50=1.0——门形同虚设。BC 几个 epoch 后泄漏 token 的 logp 上升 → w 上升 → 自增强。

**这正是我们最初要解决的问题的镜像:教师 token 走前门被赶走了(零模仿不变式成立),但教师知识藏在学生 token 里、以"条件错配"的形式从侧门回来了。不变式在 token 层成立,在信息层失守。**

### 3.4 帮凶一:20% 生成预算税(硬账)

每步生成总槽位 128(16 任务 × 8),hint 臂占 16–25%(遥测 hint_rollout_frac 0.16–0.25)→ **裸臂只剩 96–112 条 vs GRPO 的 128 条**。hint 臂 PG 训练的是"带提示"条件分布,评测永远不用;向裸上下文的唯一直接转移通道就是上面那个有毒的单 decision BC(β=0.1,每步约 7–10 行、64–393 token)。净效果 ≈ 用 80% 的 on-policy 数据跑 GRPO,再加一点毒。

### 3.5 帮凶二:治理层实际没开

- **熵恒温器 `thermostat.enable: false`**(D5 留待冒烟后设 h_ref,一直没设)——"治理层保熵"的宣称在这次 run 里没有事实基础;
- **退休从未触发**(tasks_retired_total 恒 0)、**U 门从未关闸**(u_pos_frac 恒 1.0,多数任务停在冷启动旁路)——与此前"治理时间尺度错配"分析一致(800 任务÷16/步,逐任务 EMA 100 步内仅更新约 2 次);
- 重放池不随 checkpoint 持久化,resume 后清空重建(本 run 多次崩溃续跑)。

"取其精华"的通路带毒,"去其糟粕"的通路没通电。

## 四、结论

CATALYST v1 ≈ GRPO(80% 预算)+ 20% 训练无关分布的 PG + 少量反事实 BC 毒剂 + 未上电的治理层。弱于 GRPO 不是玄学,是四项都在做负功。

核心教训一句话:**off-policyness 不只存在于"谁写的 token",也存在于"token 写作时条件于什么"。剥掉条件再克隆,就是把 off-policyness 从数据里搬进了监督信号里。**

## 五、修复方向(v2 设计输入,未定稿)

1. **止血(立即,不占卡)**:入池加语篇级审计——think 中引用参考/同事/指示的条目拒收(正则+实体接地检查:think 里断言的位置类事实必须在可观察上下文出现过)。现纯度审计只对 hint 文本做 n-gram/sha 残差,抓不到"Based on the reference"这类零 n-gram 重叠的泄漏。
2. **接地克隆**:BC 只盖被环境验证的 `<action>` span + 通过接地检查的 think token;think 值得学(初心),但只学**有据可依**的 think。
3. **让转移走环境而非走克隆**:hint 成功后同任务裸重跑,裸跑成功的轨迹才有资格作为监督(环境盖章的转移,彻底消灭条件错配);hint 的价值体现为后续批次裸成功率上升(正是 U 的定义),而非 token 克隆。
4. **预算中性**:hint 臂改为增量生成或降 rho,别再从裸臂 128 槽里扣。
5. **治理上电**:设 h_ref 启用恒温器;治理 EMA 改按窗口/批级而非逐任务(时间尺度错配已有分析);重放池随 checkpoint 持久化。
6. **实验协议**:GRPO 与 CATALYST v2 均 save_freq 10 + 3 seed(单 seed 贪心相邻步跳动 ±11.9pp,任何两方法比较都是掷硬币);评测报 sampled pass@1/pass@3。
