- The reviewer is **right** that only one correction should be applied.
- The code **already applies only one** — so there is no double-counting bug.

  `ŵ · ρ_t`. For teacher samples it *replaces* the behavior log-prob with an imputed

  "the authors have now described their method incorrectly twice."

**Eq. 9 in the submission is a genuine notational error on our part.** The honest and
much stronger rebuttal is to concede the notation, give the exact implemented form, and
show it contains exactly one correction.

## 1. What the discriminator's positive/negative classes actually are

### 1.1 Labels

`agentevolver/module/exp_manager/het_actor.py:1251-1255` builds the label:

```python
teacher_sample = (teacher_mask.sum(dim=-1) > 0) if ... else torch.zeros(...)
```

passed at `het_actor.py:1299-1306` as `is_offpolicy=teacher_sample`, and inverted in
`dr3_ratio.py:594`:

```python
labels_on = (~is_offpolicy).float().detach()  # on-policy=1, off-policy=0
```

So: **positive class = every non-teacher sequence in the batch; negative class = teacher
cache sequences.** With `exp_manager.experience_replay.enable: false` in all DUET configs
(e.g. `config/duet_paper_experiments_configs/ablations_neurips/alfworld/alfworld_qwen3b_duet_minus_bc.yaml`),
the positive class contains no replayed self-generated data — it is purely fresh rollouts.

### 1.2 Which policy generated the positives — π_θ_old, YES (this part of our claim holds)

`old_log_probs` is produced by a recompute forward pass on the **actor's rollout-time
weights**, before any optimizer step:

`agentevolver/module/trainer/ae_ray_trainer.py:2892-2894`
```python
# recompute old_log_probs
with _timer("old_log_prob", timing_raw):
    old_log_prob = self.actor_rollout_wg.compute_log_prob(batch)
```

The rollouts themselves come from the vLLM snapshot of the same weights. So the positive
class **is** generated by π_θ_old. ✅ Our premise is correct here.

### 1.3 …but three things break the clean "π_θ_old / π_β" reading

**(a) The features are the CURRENT policy's log-probs, not `old_log_probs`.**

`het_actor.py:1086` computes `log_prob` by a fresh forward pass of the *current* (partially
updated) actor, and `het_actor.py:1289-1298` feeds **that** to the discriminator:

```python
feats = compute_sequence_features(
    log_prob=log_prob.detach(),          # <-- current π_θ, NOT old_log_prob
    advantages=advantages.detach(),
    response_mask=response_mask.detach(),
    ref_log_prob=...,
    feature_mode=base_mode, ...)
```

`old_log_prob` is *never* passed to `compute_sequence_features`. So D's input space is
θ-current-dependent. The generating distributions are (π_θ_old, π_β), but the feature map
moves with θ. There is no clean factorization; "ŵ ≈ π_θ_old/π_β" over-states the precision
of a 12-dim summary-statistic classifier (`feature_mode: v3_aug`, `dr3_ratio.py:98-145`).

**(b) The training set is a rolling buffer spanning ~16 policy steps, not the current batch.**

`dr3_ratio.py:495-514` (`_push_buffer`) appends to a persistent FIFO capped at
`buffer_size`; the estimator object is created once (`het_actor.py:1203`
`if not hasattr(self, "_dr3_est")`) and survives across policy steps.

Measured from a real run
(`wandb/run-20260422_121311-ru4r1ak2/files/output.log`):
```
dr3/buf_pushed:8.000   dr3/buf_size:36.000
dr3/buf_pushed:8.000   dr3/buf_size:100.000
dr3/buf_pushed:8.000   dr3/buf_size:164.000
dr3/buf_pushed:8.000   dr3/buf_size:228.000
```
→ **64 samples pushed per policy step**; `buffer_size: 1024` ⇒ once saturated the buffer
holds **16 policy steps** of history. Age weighting (`dr3.disc_age_weight_decay: 0.02`,
`dr3_ratio.py:732-742`) recency-weights it, effective half-life ≈ 4–5 policy steps.

So the positive class is a **recency-weighted mixture of the last ~16 rollout policies**,
not "the CURRENT ROLLOUT batch". Our rebuttal draft's phrase "the CURRENT ROLLOUT batch"
is an over-claim that the reviewer can falsify in one grep. (The submission itself is
already honest about this — `03_method.tex:134` says "a rolling buffer of recent on-policy
and teacher samples".)

**(c) `ŵ` is not `D/(1−D)` at all — it is an α-RELATIVE density ratio.**

`dr3_ratio.py:844-856`:
```python
r_hat = d / (1.0 - d)
if use_relative_ratio:                                 # default True, never overridden in configs
    w = r_hat / (one_minus_alpha * r_hat + alpha_used) # w_α = p / ((1-α)p + αq)
    base_upper = 1.0 / one_minus_alpha
```
`grep -rn "use_relative_ratio" config/` returns **nothing**, so every experiment used the
default `True` (`het_actor.py:1305`).

Paper Eq. 8 writes `ŵ = D/(1−D)`. That is `r_hat`, i.e. an **intermediate variable**, not
`ŵ`. Confirmed empirically in the same log:
```
dr3/alpha:0.119   dr3/w_clip_upper:1.135
dr3/alpha:0.111   dr3/w_clip_upper:1.125
dr3/alpha:0.095   dr3/w_clip_upper:1.105
```
`w_clip_upper = 1/(1−α)` exactly, confirming the relative-ratio branch. So `ŵ ∈ (0, ~1.13]`
— it is **bounded above by ~1.13 and can never up-weight a teacher sample**. Calling it
"≈ π_θ/π_β" (an unbounded likelihood ratio) is a third notational inaccuracy the reviewer
could escalate to.

Observed `ŵ` on teacher samples in that run: `dr3/w_off_mean` = 0.937 → 0.758 → 0.663 →
0.530 → 0.711 → 0.544 (the intended fade-out).

### 1.4 Retrained every policy step? YES

`het_actor.py:1299` calls `self._dr3_est.step(...)` once **per micro-batch**, inside
`update_policy`, which runs every policy step. `dr3_ratio.py:716-752` takes
`disc_steps_per_call: 2` Adam steps per call. With `broadcast_params: true` only rank 0
optimizes and broadcasts (`dr3_ratio.py:715, 754-756`). So the discriminator is trained
~16 optimizer steps per policy step, every policy step. ✅ No lag in *training cadence*.

Caveat: WebShop configs set `dr3.w_hat_ema_alpha: 0.3`
(`config/duet_paper_experiments_configs/webshop/webshop_qwen3b_duet.yaml:109`), which
routes inference through a Polyak-averaged copy (`dr3_ratio.py:458-471, 790-793`), adding
deliberate lag there. ALFWorld configs leave it at 0 (live discriminator).

## 2. Where ŵ meets the policy ratio — the decisive finding

### 2.1 ALFWorld / default path: ŵ REPLACES the ratio, it does not multiply it

`het_actor.py:1501-1507`:
```python
dr3_w_min = float(dr3_cfg.get("w_min", 0.01))
w_hat = w_hat.clamp(min=dr3_w_min)
log_w = torch.log(w_hat.clamp_min(1e-6)).unsqueeze(-1)   # (bs,1)
old_lp_new = old_log_prob.clone()
if apply_mask.any():
    old_lp_new[apply_mask] = log_prob.detach()[apply_mask] - log_w[apply_mask]
```
then `het_actor.py:1544`: `old_log_prob = old_lp_new`, and
`het_actor.py:1603-1616` calls `repo_compute_token_loss(old_log_prob=old_log_prob, log_prob=log_prob, ...)`,
whose only ratio is `het_core_algos.py:1968-1970`:
```python
negative_approx_kl = log_prob - old_log_prob
ratio = torch.exp(negative_approx_kl)
```

**Substituting:** for a teacher token,
```
ratio = exp( log π_θ − ( sg[log π_θ] − log ŵ ) ) = ŵ · exp( log π_θ − sg[log π_θ] )
```
which **evaluates to exactly ŵ** (the two log π_θ cancel numerically) and has gradient
`∇ratio = ŵ · ∇log π_θ`.

So the denominator of the teacher ratio is **`sg[π_θ]`, i.e. the current policy detached —
NOT `π_θ_old`**. The `π_θ/π_θ_old` factor is *removed* for teacher samples, not multiplied
in. `ρ_t` of Eq. 7 applies only to on-policy samples
(`het_core_algos.py:1974-1979`, on-policy branch masked by `1 − exp_mask`; teacher samples
carry `exp_mask = 1`, cf. `ae_ray_trainer.py:161`
`teacher_token = exp_mask * teacher_mask * response_mask`).

This is the **imputation reading**, and it is clearly the design intent: teacher
trajectories have no `π_β` log-probs (`teacher_use_log_prob: false` in every DUET config),
so DR3 *reconstructs* one, `log π̂_β := sg[log π_θ] − log ŵ`, and then runs ordinary PPO.
One correction. Not two.

**Consequence for the rebuttal:** if we tell bDeY "the product telescopes", the reviewer
can compute `ratio` for a teacher token and find it equals `ŵ` identically at every
mini-batch. Our story would be falsified on inspection.

So on WebShop the teacher term is

and the `old_log_prob` repair of §2.1 is **dead code for teacher tokens** there (that

**This is a real exposure.** Eq. 9 as printed matches neither environment. If the rebuttal

## 3. Is Eq. 8's notation the source of the confusion? — Yes, partly, but Eq. 9 is the real culprit

Eq. 8 (`03_method.tex:124-132`) says `ŵ = D/(1−D) ≈ π_θ/π_β`. Read alone, that *is* "the
full off-policy correction", exactly as bDeY says. Eq. 9 (`03_method.tex:137-152`) then

Under our own definitions that product is `π_θ²/(π_β π_θ_old)` — dimensionally a
double-correction. **bDeY's reading is the only correct reading of what we wrote.** The
objection is a legitimate catch of our notation, not a misunderstanding to be argued away.

Eq. 8 is *separately* inaccurate (it prints `r_hat`, omitting the relative-ratio
transform, §1.3c), but that is not what triggered the reviewer.

Mitigating context we can lean on: `03_method.tex:153` already hedges — "We use ŵ as a
bias-mitigating replay weight rather than an exact likelihood ratio, since the teacher
cache is success-filtered." That sentence is honest and survives the fix.

## 4. Accurate statement we CAN make

1. DUET applies **exactly one** importance correction to teacher samples. ✅ verifiable.
2. That correction is `ŵ`, applied by **imputing** the missing behavior log-probability
   `log π̂_β := sg[log π_θ] − log ŵ` and then running the ordinary single PPO ratio, so the
   teacher ratio evaluates to `ŵ` and the gradient is `ŵ ∇log π_θ`. ✅ verifiable.
3. `ρ_t` (Eq. 7) applies to **on-policy samples only**. ✅ verifiable.
4. `ŵ` is an **α-relative** density ratio `r̂/((1−α)r̂+α) ∈ (0, 1/(1−α)]`, a
   variance-controlled surrogate, not an exact likelihood ratio. ✅ verifiable, and the
   bound `1/(1−α)` is directly observable in logs as `dr3/w_clip_upper`.
5. The discriminator is retrained every policy step on a recency-weighted rolling buffer
   of recent rollouts vs. the teacher cache; positives are generated by recent rollout
   policies (π_θ_old and its immediate predecessors). ✅ verifiable.
6. Eq. 9 as printed is a **notational error**; we correct it.

What we must **NOT** say:
- ✗ "ŵ·ρ_t telescopes to π_θ/π_β" — the product does not exist in the code.
- ✗ "the positive class is the current rollout batch" — it is a ~16-step rolling buffer.
- ✗ "ŵ = D/(1−D)" — that is the intermediate `r̂`.
- ✗ any single formula presented as covering both ALFWorld and WebShop.

## 5. Proposed notation fix for `sections/03_method.tex`

Replace Eq. 8 and Eq. 9 (`03_method.tex:124-152`) with:

```latex
% --- Eq. 8: what the discriminator gives us -------------------------------
Let $\hat r(\tau)=\frac{D_\phi(\tau)}{1-D_\phi(\tau)}$ be the discriminator odds for a
trajectory $\tau$ ($D_\phi$ is a sequence-level classifier, so $\hat r$ is a
per-trajectory quantity), and let $\alpha$ be the teacher fraction of the batch.
DUET uses the $\alpha$-\emph{relative} density ratio
\begin{equation}
\hat w(\tau)
=
\frac{\hat r(\tau)}{(1-\alpha)\,\hat r(\tau)+\alpha}
\;\in\;\Bigl(0,\tfrac{1}{1-\alpha}\Bigr],
\qquad
\hat r(\tau)\;\approx\;
\frac{\pi_{\theta_{\mathrm{old}}}(\tau)}{\pi_\beta(\tau)},
\label{eq:dr3_ratio}
\end{equation}
a bounded, variance-controlled surrogate for the teacher--student likelihood ratio
rather than the ratio itself.

% --- Eq. 9: ONE correction, via imputation --------------------------------
Teacher log-probabilities are unavailable, so instead of multiplying
Eq.~\eqref{eq:grpo_ratio} by $\hat w$ we \emph{impute} the missing behaviour
log-probability from $\hat w$,
\begin{equation}
\log\hat\pi_\beta(a_t\mid s_t)
\;:=\;
\mathrm{sg}\bigl[\log\pi_\theta(a_t\mid s_t)\bigr]-\log\hat w(\tau),
\label{eq:dr3_impute}
\end{equation}
where $\mathrm{sg}[\cdot]$ is the stop-gradient operator, and then apply the
\emph{ordinary single} PPO ratio
\begin{equation}
\rho^\beta_t
=
\frac{\pi_\theta(a_t\mid s_t)}{\hat\pi_\beta(a_t\mid s_t)}
\;=\;\hat w(\tau),
\qquad
\nabla_\theta\rho^\beta_t=\hat w(\tau)\,\nabla_\theta\log\pi_\theta(a_t\mid s_t),
\label{eq:dr3_teacher_ratio}
\end{equation}
\begin{equation}
\mathcal{L}_{\mathrm{PG}}^{\mathrm{tch}}(\theta)
=
-\mathbb{E}_{(s,a)\sim G^\beta}
\bigl[\hat A^\beta\cdot\mathrm{clip}(\rho^\beta_t,\,1-\varepsilon,\,1+\varepsilon)\bigr].
\label{eq:dr3_loss}
\end{equation}
Teacher samples therefore receive \emph{exactly one} importance correction:
$\hat w$ \emph{replaces} the on-policy ratio $\rho_t$ of
Eq.~\eqref{eq:grpo_ratio} rather than multiplying it. $\rho_t$ is applied to
on-policy samples only.
```

Plus two one-line additions:
- After Eq. 8: keep `03_method.tex:133-135` (features / rolling buffer) but change
  "so $\hat w$ tracks the evolving student distribution" → "so $\hat w$ tracks a
  recency-weighted mixture of the most recent rollout policies (buffer span
  $\approx 16$ policy steps in our runs)."
- In `appendix_c_impl.tex`: state the WebShop variant — with
  `dr3.use_policy_shaping=true` the teacher ratio is
  $\hat w(\tau)\cdot g(\tau)\cdot \pi_\theta/(\pi_\theta+\beta)$, LUFFY-style shaping
  in place of Eq. \eqref{eq:dr3_teacher_ratio}, still a single $\hat w$ factor.
